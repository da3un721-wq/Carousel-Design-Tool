## 0. 결론 요약

1. **명세서에 있는 기능 중 "아예 불가능한" 기능은 없다.** 모두 웹 단계 또는 앱 단계에서 구현할 방법이 있다.
2. **맥북(앱) 단계가 꼭 필요한 기능**: 펜슬 더블탭/스퀴즈, 아이패드 설치 폰트 사용, 배경 제거, iCloud 동기화, 인스타로 바로 보내기, 안정적인 동영상 내보내기.
3. **가장 큰 위험 3가지**
   - **펜슬 그리기 부드러움 (DR-20)**: 웹에서는 Procreate만큼 부드럽기 어렵다. 앱으로 포장해도 자동으로 좋아지지 않는다 (1-D 참고).
   - **동영상 MP4 내보내기 (VD-09, P0)**: 툴 전체에서 가장 어렵다. 웹 단계에서는 제약이 크다 (1-E 참고).
   - **캔버스 위 한글 텍스트 편집 (TX-03, TX-20)**: 직접 만들어야 하는 부분이 많고, 품질 체감이 가장 큰 부분이다 (1-C 참고).
4. **기능끼리 부딪히는 부분 11곳**을 찾았고 모두 해결책을 정했다 (3장). 손그림은 픽셀 방식으로 확정 (v0.5).
5. **실기기 확인 목록 13개**는 개발 첫 주에 아이패드에서 직접 테스트해서 확정한다 (4장).

## 1. 전체 구조에 영향을 주는 핵심 사항

개별 기능보다 먼저 정해야 하는 것들. 처음에 잘못 정하면 나중에 크게 고쳐야 한다.

### A. 캔버스 크기 한계 → "화면 크기만큼만 그리는" 구조 필수

- iPad Safari는 캔버스 하나의 크기를 약 **1,677만 픽셀**(예: 4096×4096)로 제한한다고 알려져 있다. 캔버스 전체가 쓸 수 있는 메모리에도 한계가 있다(기기와 버전마다 다름).
- 이어 보기 모드로 4:5 슬라이드 20장을 붙이면 **21,600×1,350 = 약 2,900만 픽셀**이라 한 장짜리 캔버스로는 불가능하다.
- **해결**: 화면에 보이는 크기의 캔버스 하나에, 보이는 부분만 그린다. 내보낼 때는 슬라이드 한 장씩 따로 그린다. 디자인 툴들이 일반적으로 쓰는 방식이다.
- 내보내기 최대 크기: 9:16 2배(2160×3840) = 약 830만 픽셀이라 한계 안이다 ✅

### B. 손그림 저장 방식: **픽셀로 확정** (v0.5)

| | 선 단위(벡터) | 픽셀 ✅ 선택 |
|---|---|---|
| 비슷한 앱 | 굿노트, Notability, Figma 연필 | Procreate |
| 확대해도 선명 | ✅ | ❌ (해상도 고정) |
| 그린 뒤 색, 굵기 바꾸기 | ✅ 쉬움 | ⚠️ 색만 가능 |
| 올가미 | 선 단위로 선택 | 영역을 오려냄 (자연스러움) |
| 지우개 | 부분 지우기 어려움 ★★★★ | ✅ 쉬움 |
| 질감 브러쉬(연필, 에어브러시) | ⚠️ 표현 한계 | ✅ 자연스러움 |
| 저장 용량 | 작음 | 큼 |

**선택 이유**: 질감과 표현력이 중요하고, 슬라이드 크기에 맞춰 그리므로 해상도 문제가 크지 않다.

**픽셀 방식에서 챙길 것**

- **해상도**: 손그림은 슬라이드 실제 해상도(폭 1080 기준)로 그린다. 손그림 레이어를 크게 키우면 흐려진다 (Procreate와 같음). 2배 내보내기(EX-09, P2)를 할 때는 손그림만 1배 품질이 되므로, 그때 "손그림 2배 해상도" 옵션을 검토한다 (메모리 4배).
- **메모리**: 슬라이드 한 장 크기의 손그림 레이어는 작업 중 약 6MB를 차지한다. Safari 캔버스 메모리 한계(1-A) 때문에 **지금 그리는 레이어만 작업 상태로 두고, 나머지는 압축 이미지로 보관**한다.
- **레이어 크기**: 여러 장에 걸쳐 그릴 수 있도록, 그린 범위만큼 레이어가 자동으로 늘어난다. 빈 곳은 저장하지 않는다.
- **실행 취소**: 획마다 레이어 전체를 저장하지 않고 **바뀐 영역만** 저장한다 (50단계를 메모리 안에서 유지).
- **브러쉬 엔진**: 질감 브러쉬까지 고려해 처음부터 그래픽 칩 계산(WebGL) 기반으로 만든다. 그리기 성능(1-D)에도 유리하다.

### C. 텍스트 엔진은 직접 만들어야 함

- 캔버스의 기본 글자 기능만으로는 장평, 줄마다 배경 박스, 부분 서식, 한글 줄바꿈 규칙, Figma식 자간/행간을 정확히 처리할 수 없다.
- **해결**: 글자 위치를 직접 계산하는 "텍스트 배치 엔진"을 만든다. P0는 기본형으로 시작하고, 부분 서식(TX-20)에서 크게 확장한다.
- **한글 입력**: 캔버스에는 입력 기능이 없어서, 보이지 않는 입력창으로 글자를 받아 캔버스에 그린다. 조합 중인 글자(ㅎ → 하 → 한), 커서, 선택 영역을 직접 그려야 한다. ❓ 블루투스 키보드와 한글 입력 조합은 실기기 테스트 필수.
- **결정 필요(작음)**: 한글 줄바꿈을 글자 단위로 할지, 띄어쓰기(어절) 단위로 할지. Figma처럼 옵션으로 둘 수도 있다.

### D. 펜슬 그리기 부드러움 (DR-20): 가장 솔직하게 말해야 하는 부분

- **Safari는 기본적으로 화면을 1초에 약 60번만 다시 그린다.** 120Hz(ProMotion) 아이패드에서도 그렇다. 사용자가 Safari 설정의 숨은 실험 기능을 꺼야 120Hz가 된다는 자료가 있고, 홈 화면 앱(PWA)에는 그 설정조차 적용되지 않는다는 보고도 있다.
- **펜슬 입력도 일부만 전달된다.** 펜슬은 1초에 240번 위치를 보내지만, 웹은 화면 갱신 단위로 묶어서 받는다. 묶인 입력을 모두 꺼내는 기능(getCoalescedEvents)은 iOS 18.2부터 Safari에 들어왔다는 보고가 있지만 구현이 불완전하다는 지적도 있다. Pencil Pro 아이패드에서 Safari 펜 입력 빈도가 낮아 곡선이 각지게 그려진다는 개발자 보고도 있다.
- **결과**: 웹 단계 그리기는 "충분히 쓸 만하지만 Procreate만큼 착 붙지는 않는" 수준이 목표다. 손떨림 보정(스무딩)과 곡선 보간으로 체감을 최대한 끌어올린다.
- **앱으로 포장해도 자동으로 좋아지지 않는다.** 그림은 여전히 앱 안의 웹 화면에서 그려지기 때문이다. 2단계에서 개선하려면 **그리는 순간에만 아이패드 기본 그리기 화면(Metal 또는 PencilKit)을 위에 띄우고, 펜을 떼면 웹 캔버스로 넘기는** 방식이 필요하다. 난이도 ★★★★★.
- **판단**: 이 툴의 중심은 레이아웃과 편집이고 손그림은 보조라면 웹 수준으로 충분할 가능성이 높다. **1단계 초반에 그리기 시제품을 만들어 직접 써보고 판단**하는 것을 추천한다.

### E. 동영상 처리 방식

| 방법 | 단계 | 장점 | 단점 |
|---|---|---|---|
| 화면 녹화 방식 (MediaRecorder) | 🌐 | 비교적 쉬움, Safari에서 MP4로 저장 가능 | **영상 길이만큼 시간이 걸림**(30초 영상 = 30초). 처리 중 버벅이면 프레임이 빠짐. 화면이 꺼지거나 다른 앱으로 가면 실패 |
| 프레임 단위 인코딩 (WebCodecs) | 🌐 | 빠르고 정확함 | Safari에서 **오디오 인코딩까지 완전 지원은 iPadOS 26부터**로 보임. 난이도 ★★★★★ |
| 아이패드 영상 엔진 (AVFoundation) | 🍎 | 빠르고 안정적. 자르기, 크롭, 오디오, 위에 이미지 얹기 모두 표준 기능 | 맥 필요. 영상 위 오브젝트에 **블렌드 모드**가 걸려 있으면 재현이 어려움 ⚠️ |

- **추천**: 1단계에서 화면 녹화 방식으로 **슬라이드당 최대 10초** 영상 내보내기를 만들고, 2단계에서 AVFoundation으로 교체해 길이 제한을 푼다. 10초면 내보내기 대기 시간이 짧고 중간에 끊길 위험도 작다. 편집하지 않은 영상은 원본을 그대로 내보내서 녹화 자체를 피한다. ffmpeg를 웹에서 돌리는 방법(ffmpeg.wasm)은 아이패드 메모리와 속도 때문에 추천하지 않는다.

### F. 저장 안정성

- 작업물은 브라우저 저장소(IndexedDB)에 저장한다.
- Safari는 **홈 화면에 추가하지 않은 사이트**의 데이터를 7일 동안 사용하지 않으면 지울 수 있다. 홈 화면 앱은 예외다. 그래서 1단계에서는 **반드시 홈 화면에 추가해서 사용**하고, 프로젝트 파일 백업(PJ-06)을 P0로 둔다.
- 앱 단계에서는 이 문제가 없다.

### G. 이미지 보정은 WebGL로

- Safari의 캔버스 필터 기능(ctx.filter)은 오랫동안 지원되지 않았고, 현재 정식 지원 버전을 확인하지 못했다.
- **해결**: 밝기, 대비, 채도, 색온도, 흐림을 WebGL(그래픽 칩 계산)로 직접 구현한다. 더 빠르고 Safari 지원 여부와도 무관하다. ✅

### H. 인스타 상표 (출시 시)

- 미리보기를 인스타와 "닮게" 만드는 것은 괜찮지만, 인스타 로고와 아이콘을 그대로 쓰거나 앱 이름에 "Instagram", "Insta"를 넣으면 메타의 상표 정책과 앱스토어 심사(지식재산권 조항)에 걸릴 수 있다.
- **해결**: 자체 아이콘으로 비슷한 화면을 만들고, 앱 이름에서 인스타 표현을 뺀다. 명세서 20장에 반영했다.

| # | 충돌 | 해결 | 상태 |
|---|---|---|---|
| 1 | **두 손가락 스와이프로 슬라이드 넘기기(CV-07)** vs **두 손가락 드래그로 화면 이동(CV-14)**: 같은 동작이라 구분 불가 | 한 장씩 보기 + 화면 맞춤 상태에서만 빠르게 튕기면 넘기기. 확대한 상태에서는 화면 이동 (사진 앱 방식) | ✅ v0.3 반영 |

| 6 | **프로젝트에 폰트 포함(FT-04)** vs **폰트 라이선스**: 프로젝트 파일을 남에게 주면 폰트 재배포가 될 수 있음 | "폰트 빼고 내보내기" 옵션 | ✅ v0.3 반영 |

## 5. 난이도 상위 기능 (개발 일정 잡을 때 참고)

| 순위 | 기능 | 난이도 | 우선 |
|---|---|---|---|
| 1 | MP4 내보내기 (VD-09, EX-05) | ★★★★★ | P0 |
| 2 | 그리기 반응 속도 (DR-20) | ★★★★★ | P0 |
| 3 | 부분 서식 (TX-20) | ★★★★★ | P1 |
| 4 | 캔버스 위 한글 편집 (TX-03) | ★★★★ | P0 |
| 5 | 클리핑 + 블렌드 + 그룹 합성 (LY-07, LY-09) | ★★★★ | P1 |
| 6 | 펜툴과 점 편집 (SH-06, SH-07) | ★★★★ | P1 |
| 7 | 도형 보정 (DR-09) | ★★★★ | P2 |
| 8 | 말풍선 외곽선 합치기 (SH-13) | ★★★★ | P1 |
| 9 | 경계 동영상 자르기 (CV-06) | ★★★★ | P1 |
| 10 | iCloud 동기화 (PJ-08) | ★★★★ | P2 |

> P0 중 ★★★★ 이상은 **그리기 반응 속도**, **한글 편집**, **MP4 내보내기** 세 개다. 셋 다 1단계 초반에 시제품으로 먼저 검증하는 것을 추천한다.
>
> MP4 내보내기 부담을 줄이는 방법: 편집하지 않았고 위에 아무것도 얹지 않은 영상 슬라이드는 원본 파일을 그대로 내보낸다(인코딩 불필요). 자르기, 크롭, 얹기가 들어간 슬라이드만 새로 만든다.

## 6. IA와 디자인 프로토타입 참고사항

IA와 프로토타입에는 P0~P2 기능을 모두 넣는다. 설계할 때 아래를 함께 반영하면 나중에 화면을 다시 만들 일이 줄어든다.

- **🍎 기능도 자리를 미리 잡는다**: 펜슬 더블탭/스퀴즈 설정, iCloud 동기화, 배경 제거 버튼. 웹 단계에서는 숨기거나 "앱에서 지원" 표시.
- **키보드 없는 상태가 기본**: 모든 기능이 터치만으로 가능해야 하고, 단축키는 빠른 길로 생각한다 (OB-15).
- **제스처 설정 화면**: 손가락 제스처 켜기/끄기, 펜슬 동작 선택, 손가락으로 그리기 끄기.
- **실제 크기 설정**: 휴대폰 화면 모드용 아이패드/아이폰 모델 선택 (IG-03).
- **경고 메시지 자리**: 혼합 비율 경계 경고, 인스타 규격 벗어남, 폰트 없음, 영상 길이 초과.
- **인스타 미리보기는 자체 아이콘으로** (1-H).
