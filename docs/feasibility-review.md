# 캐로킷 (CaroKit): 구현 가능성 검토 (기능 명세서 v0.9 · iPad 앱 기준)

> 기능 명세서의 P0, P1, P2 전체 항목을 **iPad 네이티브 앱(Swift)** 기준으로 하나씩 검토한 문서.
> 확인한 사실과 추정을 구분했고, 개발 초기에 직접 확인해야 하는 것은 ❓로 표시했다.
> 이전 버전(웹앱 기준)에 있던 Safari 관련 제약(60fps 제한, 캔버스 크기 제한, 저장소 삭제, 설치 폰트 불가, 영상 녹화 방식 등)은 앱으로 바꾸면서 대부분 없어졌다.

---

## 0. 결론 요약

1. **명세서의 모든 기능은 iPad 앱으로 구현할 수 있다.** 애플이 기본으로 제공하는 기술(펜슬, 텍스트, 영상, 사진, 폰트)로 대부분 해결된다.
2. **앱으로 바꾸면서 쉬워진 것**: 한글 텍스트 편집과 부분 서식, 펜슬 더블탭·스퀴즈·호버, 설치 폰트, 동영상 처리 전반, 사진 앱 순서대로 저장, 글자 선택되는 PDF, 이미지 보정, 배경 제거
3. **여전히 어려운 것 (큰 위험 3가지)**
   - **브러쉬 엔진 (DR-05, DR-20)**: 필압·기울기 켜기/끄기, 직선 보정, 형광펜 규칙을 지키려면 브러쉬 엔진을 직접 만들어야 한다 (1-B).
   - **영상 + 블렌드 합성 내보내기 (VD-09)**: 영상 위 오브젝트에 블렌드 모드가 걸리면 직접 만든 영상 합성기가 필요하다 (1-D).
   - **레이어 합성 렌더러 (LY-07, LY-09)**: 클리핑 + 블렌드 + 그룹이 겹치는 경우를 모두 맞게 그리는 렌더러 (1-A).
4. **개발과 테스트에는 Mac이 필요하다.** 개발 환경과 출시 과정은 1-H와 [tech-design.md](tech-design.md) 참고.

## 1. 전체 구조에 영향을 주는 핵심 사항

### A. 렌더링: 화면에 보이는 것만 그리는 구조

- 캔버스는 **Metal(아이패드 그래픽 기술) 기반으로 직접 그리는 렌더러**를 추천한다. 블렌드 모드 16종, 클리핑, 그룹 합성, 효과를 정확하게 제어할 수 있다.
- 이어 보기 모드에서 20장을 붙여도, **화면에 보이는 영역만 그리고** 바뀌지 않는 오브젝트는 미리 그려 둔다. 웹처럼 캔버스 크기 제한은 없지만 아이패드 메모리는 한정돼 있다.
- **벡터 오브젝트는 그때그때 다시 그린다** (명세서 19장 선명도). 텍스트, 도형, 펜툴, 말풍선은 모양 정보(글자, 경로)만 저장하고, 화면 확대 배율과 내보내기 배율에 맞춰 매번 새로 그린다. 한 번 그린 그림을 늘려서 쓰면 흐려진다 (경쟁 앱 SWVY에서 텍스트를 키우면 흐려지는 문제). 미리 그려 둔 그림은 배율이 바뀌면 다시 만든다. ✅ Core Text와 Core Graphics 경로로 가능
- 클리핑 + 블렌드 + 그룹이 겹치면 별도 작업 영역에서 순서대로 합성해야 한다. 원리는 확실하지만 경우의 수가 많아 난이도가 높다.

### B. 손그림: 픽셀 방식 + 직접 만드는 브러쉬 엔진

- 손그림은 **픽셀 방식으로 확정** (v0.5). 질감 표현, 지우개, 페인트통이 자연스럽다.
- **애플 기본 그리기 도구(PencilKit)** 는 반응이 빠르고 올가미·지우개가 들어 있지만, 선 단위(벡터) 방식이고 필압 끄기, 직선 보정, 형광펜 규칙, 질감 브러쉬를 우리 마음대로 바꿀 수 없다. → **명세서를 지키려면 브러쉬 엔진을 직접 만든다** (Metal 기반).
- 앱에서는 **120Hz 화면**과 펜슬의 **예측 입력**(펜이 갈 곳을 미리 알려줌), **촘촘한 입력**(1초에 240번)을 모두 쓸 수 있어 Procreate 수준이 가능하다. 결과는 엔진 품질에 달려 있다.
- 챙길 것
  - **해상도**: 슬라이드 실제 해상도(폭 1080)로 그린다. 크게 키우면 흐려진다 (Procreate와 같음)
  - **메모리**: 지금 그리는 레이어만 작업 상태로 두고 나머지는 압축 보관
  - **레이어 크기**: 그린 범위만큼 자동으로 늘어남 (여러 장에 걸쳐 그리기)
  - **실행 취소**: 획마다 바뀐 영역만 저장
- **추천**: 개발 초기에 브러쉬 엔진 시제품을 먼저 만들어 직접 써보고 판단한다.

### C. 텍스트: 아이패드 텍스트 시스템 활용

- 아이패드 텍스트 시스템(TextKit, Core Text)이 **자간, 행간, 정렬, 밑줄·취소선, 이탤릭, 부분 서식**을 기본으로 지원한다. 웹 기준에서 가장 어려웠던 **부분 서식(TX-20)이 쉬워졌다.**
- **한글 입력**: 아이패드 기본 텍스트 편집을 쓰면 한글 조합, 커서, 선택, 블루투스 키보드가 기본으로 된다. 캔버스의 확대·회전 상태와 편집 화면을 맞추는 부분만 직접 만든다.
- 직접 만들어야 하는 것: 장평, 바깥 테두리, 줄마다 배경 박스, Figma와 같은 "자동" 행간, 곡선 텍스트
- **결정 필요(작음)**: 한글 줄바꿈 기본값 (IA에서 띄어쓰기 단위로 정함, 변경 가능)

### D. 동영상: AVFoundation

| 기능 | 방법 | 난이도 |
|---|---|---|
| 자르기, 크롭, 소리 끄기, 오디오 넣기, 페이드, 배속, 소리 높낮이 유지 | 아이패드 영상 엔진(AVFoundation) 기본 기능 | ★~★★ |
| 영상 위에 텍스트·도형·손그림 얹어 내보내기 | 오브젝트를 이미지로 만들어 영상과 합성 | ★★★ |
| 영상 위 오브젝트에 **블렌드 모드** 적용 | 직접 만든 영상 합성기 (Core Image/Metal) | ★★★★ |

- 내보내기는 **영상 길이보다 빠르게** 처리되고, 화면 녹화 방식이 아니라서 중간에 끊길 걱정이 적다.
- 명세서의 **10초 제한은 이제 기술 제약이 아니다.** 첫 버전 범위로 유지하고, 나중에 늘릴 수 있다.

### E. 저장

- 프로젝트는 앱 저장 공간에 **폴더 하나(내용 정보 + 이미지·영상·폰트 파일)** 로 저장한다. 웹처럼 데이터가 지워질 걱정이 없다.
- 자동 저장 + 크래시 복구, 프로젝트 파일 내보내기(백업). iCloud 동기화는 P2.

### F. 이미지

- 보정(밝기, 대비, 채도, 색온도, 흐림)은 **Core Image** 필터로 쉽게 구현한다.
- 배경 제거는 아이패드 내장 **피사체 분리(Vision)** 를 쓴다.

### G. 인스타 상표 (출시 시)

- 미리보기를 인스타와 "닮게" 만드는 것은 괜찮지만, 인스타 로고와 아이콘을 그대로 쓰거나 앱 이름에 "Instagram", "Insta"를 넣으면 메타의 상표 정책과 앱스토어 심사에 걸릴 수 있다. → 자체 아이콘 사용, 앱 이름에서 인스타 표현 빼기.

### H. 개발 환경과 출시 과정

| 단계 | 필요한 것 | 비용 |
|---|---|---|
| 개발 | Mac + Xcode(무료) + Claude Code. Mac에서 빌드하고 시뮬레이터로 화면 확인 | 0원 |
| 내 아이패드에서 써보기 | Xcode로 케이블 연결해 설치. 아이패드 "개발자 모드" 켜기. 7일마다 재설치 | 0원 |

| 정식 출시 | 앱스토어 심사 | (위와 같음) |

- **Mac 사양 확인 필요**: 최신 Xcode는 최신 macOS가 필요해서 오래된 Mac은 개발용으로 못 쓸 수 있다.

**계정 연동 조건**
1. **프로페셔널 계정만**: 개인 계정용 API(Basic Display API)는 **2024년 12월 4일 종료** ✅. 지금 API는 비즈니스·크리에이터 계정 대상 ✅ (크리에이터 계정 전환은 인스타 앱에서 무료로 가능 🟡)
2. **서버 필요**: 로그인 후 토큰을 받는 과정에 앱 비밀 키가 들어가서, 메타 문서가 **서버에서 처리하라**고 안내 ✅. 토큰은 약 60일 유효, 갱신 필요 ✅ → "서버 없음" 원칙의 예외. 작은 서버(로그인 처리만)와 운영비 발생
3. **메타 앱 검수**: 필요한 권한마다 검수 신청, 사용 장면 화면 녹화 제출. 권한에 따라 비즈니스 인증도 필요할 수 있음 🟡
4. **개인정보**: 개인정보처리방침에 인스타 데이터 처리 내용 추가, 연결 해제 시 데이터 삭제

**참고: API로 바로 올리기**
- API로 캐러셀을 올리면 **최대 10장** 🟡 (인스타 앱에서는 20장). 하루 게시 수 제한도 있음 → 캐로킷은 지금처럼 **사진 앱 저장 + 인스타 앱에서 올리기**(EX-08, EX-10)를 기본으로 유지

**위험**: 메타는 API를 자주 바꾼다 (Basic Display 종료, 지표 폐지). 혼자 개발할 때 유지보수 부담이 크므로 **1단계를 먼저** 내고 2단계는 사용자 반응을 보고 결정한다.

| # | 충돌 | 해결 | 상태 |

| 1 | **두 손가락 스와이프로 슬라이드 넘기기(CV-07)** vs **두 손가락 드래그로 화면 이동(CV-14)** | 한 장씩 보기 + 화면 맞춤 상태에서만 빠르게 튕기면 넘기기. 확대한 상태에서는 화면 이동 (사진 앱 방식) | ✅ |

| 3 | **Shift+탭, Shift 회전 스냅, Alt 간격 표시, Alt 드래그 복제**: 키보드가 없으면 못 씀 | 다중 선택 버튼, 자동 스냅, 드래그 중 간격 자동 표시, 복제 버튼 (OB-15) | ✅ |
| 4 | **한글 입력 상태에서 단축키**: 한글 상태면 V가 ㅍ로 들어옴 | 글자 대신 키 위치로 인식 | ✅ (개발 초기 확인) |
| 5 | **세 손가락/네 손가락 탭(DR-14)** vs **아이패드 시스템 제스처** | 앱에서 편집 제스처를 끄는 설정 적용 + 제스처별 켜기/끄기 + 실행 취소 버튼 상시 표시 | ✅ (개발 초기 확인) |
| 6 | **프로젝트에 폰트 포함(FT-04)** vs **폰트 라이선스** | "폰트 빼고 내보내기" 옵션 | ✅ |
| 7 | **방향키 1px 이동(OB-03)** vs **방향키 슬라이드 넘기기(CV-07)** | 선택한 오브젝트가 있으면 이동, 없으면 슬라이드 넘기기. 텍스트 편집 중에는 커서 이동 | ✅ |
| 8 | **손그림 저장 방식**: 벡터냐 픽셀이냐 | 픽셀 방식 (1-B) | ✅ |
| 9 | **애플 기본 그리기 도구(PencilKit)** vs **명세서의 브러쉬 요구사항** | 브러쉬 엔진 직접 개발 (1-B) | ✅ |
| 10 | **원고의 Enter**(새 단락) vs **캔버스 텍스트의 Enter**(줄바꿈) | 원고 패널에서만 Enter가 새 단락 | ✅ |
| 11 | **원고 연결(SC-11)** vs **부분 서식(TX-20)** | 원고에서 글자를 고치면 바뀐 부분 앞뒤의 서식을 최대한 유지하고, 맞출 수 없으면 단락 서식으로 되돌림 | ✅ (개발 시 세부 규칙 확정) |

## 6. UI 디자인 참고사항

- **키보드 없는 상태가 기본**: 모든 기능이 터치만으로 가능해야 하고, 단축키는 빠른 길로 생각한다 (OB-15).
- **제스처 설정 화면**: 손가락 제스처 켜기/끄기, 펜슬 더블탭·스퀴즈 동작 선택, 손가락으로 그리기 끄기.
- **경고 메시지 자리**: 혼합 비율 경계 경고, 인스타 규격 벗어남, 폰트 없음, 영상 길이 초과.
- **인스타 미리보기는 자체 아이콘으로** (1-G).
