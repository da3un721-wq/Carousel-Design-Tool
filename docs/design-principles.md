# 캐로킷 (CaroKit): 디자인 원칙 (v0.1 초안)

> UI 디자인의 기준. 콘셉트를 고를 때와 화면을 그릴 때 이 문서로 판단한다.

---

## 0. 우리가 추구하는 것

> **디자인을 하는 건 사용자다. 앱이 디자인을 하면 안 된다.**

- 1순위: **심플하고, 직관적이고, 쓰기 쉬울 것**
- 하지만 "디자인이 안 된 것", "흔한 것"은 아니다
- **미니멀하지만 아이덴티티가 있는 디자인**

한 줄로: **도구는 조용히, 작품은 크게.**

### 참고할 생각: "Less, but better"

- 디터 람스(브라운)의 좋은 디자인 원칙 중 마지막: **"좋은 디자인은 가능한 한 적게 디자인한 것"** (Weniger, aber besser)
- 우연이지만 캐러셀과 이어지는 이야기가 있다: 코닥 **Carousel-S(1963, MoMA 소장)** 를 디자인한 한스 구겔로트는 울름 조형대학(HfG Ulm) 제품디자인 학과를 이끈 교수이고, 디터 람스와 함께 브라운 라디오·전축 **SK 4**(1956, "백설공주의 관", MoMA 소장)를 디자인했다. 장식 없이 기능으로 아이덴티티를 만든 디자인
- 캐로킷도 같은 방식: **장식으로가 아니라 기능과 정돈으로 알아보게 한다**

## 1. 원칙

| # | 원칙 | 뜻 | 판단 질문 |
|---|---|---|---|
| 1 | **작품이 주인공** | 캔버스가 화면 대부분. 패널은 접을 수 있고, 집중 모드에서는 다 숨김 | 캔버스보다 UI가 먼저 눈에 들어오나? |
| 2 | **색은 사용자의 것** | UI는 무채색. 사용자가 색을 판단할 때 UI 색이 끼어들지 않게 | 이 색이 사용자 작품 색 판단을 방해하나? |
| 3 | **모든 요소는 일을 한다** | 기능 없는 장식은 넣지 않는다. 장식처럼 보이는 것도 정보를 전달해야 함 | 이걸 빼면 기능이 사라지나? 아니면 뺀다 |
| 4 | **한 번 보면 안다** | 아이콘과 이름만으로 뜻이 통하게. 처음 보는 사람도 설명 없이 | 설명(툴팁)이 꼭 있어야만 이해되나? |
| 5 | **조수처럼 챙긴다** | 문제를 미리 알려주되 작업을 막지 않는다. 팝업보다 옆에 조용히 붙는 메모 | 이 알림이 작업 흐름을 끊나? |
| 6 | **펜슬과 손가락 먼저** | 누르는 영역은 넉넉하게, 자주 쓰는 건 손 닿는 곳에. 키보드는 있으면 더 빠른 것 | 펜슬 하나만 들고도 다 되나? |
| 7 | **익숙한 건 그대로** | 화면 배치, 아이콘 은유, 단축키, 선택 핸들 같은 디자인 툴 관례는 따른다 (어포던스). 아이덴티티는 2장의 시그니처에만 둔다. [디자인 툴 공통 UI](references/design-tool-ui-patterns.md) | 이걸 바꾸면 사용자가 다시 배워야 하나? |

## 2. 아이덴티티는 어디에 두나 (시그니처)

화면 전체가 아니라 **정해진 몇 곳에서만** 캐로킷다움이 드러나게 한다. 후보:

| 시그니처 | 내용 | 일을 하는 이유 |
|---|---|---|
| **슬라이드 경계 표시** | 이어지는 캔버스에서 장과 장 사이를 표시하는 캐로킷만의 모양 (예: 재단선, 코너 마크) | 어디서 잘리는지 알려줌. 캐러셀 툴에만 있는 요소라 가장 캐로킷다움 |
| **강조색 하나** | 지금 선택된 것, 지금 장, 조수의 안내에만 쓰는 색 1개 | "지금 여기"를 알려줌 |
| **숫자** | 장 번호(01/20), 좌표, 크기에 쓰는 숫자 글꼴과 표기 방식 | 캐러셀은 순서가 중요. 숫자가 많은 툴 |
| **움직임과 손맛** | 장이 넘어가거나 경계에 붙을 때의 짧은 움직임과 진동 | 스냅, 넘김이 됐다는 확인 |
| **말투** | 짧고 담백한 조수 말투 | 경고와 안내가 부담스럽지 않게 |
| **모양 규칙** | 모서리 둥글기, 선 두께, 아이콘 스타일을 하나의 규칙으로 | 정돈된 느낌 = 흔하지 않은 느낌 |

이전에 나온 콘셉트 비유(편집실, 슬라이드 프로젝터, 작업대)는 **화면 테마가 아니라** 위 시그니처를 정할 때 쓰는 **숨은 재료**로 쓴다. 예: 경계 표시는 재단선에서, 넘김 손맛은 프로젝터 트레이에서.

## 2-1. 정한 스타일 (와이어프레임 v0.1)

[CaroKit Figma 파일 › WireFrame 페이지](https://www.figma.com/design/fRGnDrQsZ5Iyh8eUxt5sOx)의 "00 와이어프레임 규칙"과 같은 내용.

| 항목 | 결정 |
|---|---|
| **모양** | **라운딩 0.** 모든 모서리 직각 (요즘 흔한 둥근 UI와 다르게). 예외: 작품 카드(홈 · 시리즈 그리드 썸네일)만 4px로 아주 살짝 |
| **선** | 면 대신 선으로 영역을 나눔. 구분선 1px 회색(D1D1D1), 테두리 1px 검정(121212), 선택·현재 2px 검정 |
| **상태** | 켜짐·선택 = 검정 채움 또는 2px 선. 도구 바는 왼쪽 2px 막대 |
| **상단 바** | 개별 버튼이 아니라 **진한 띠 하나**(#262626)에 칸이 붙은 형태. 글자·아이콘은 밝게. **지금 보고 있는 탭 · 열린 칸만 흰색으로 뚫려 아래 화면과 이어짐** (폴더 탭). 홈 · 시리즈 · 에디터 모두 같은 규칙 |
| **느낌** | 어도비 툴처럼 선을 잘 쓰되, 더 직관적이고 친절하고 미니멀하게 |
| **글꼴** | 한글 UI: **IBM Plex Sans KR**, 숫자: **IBM Plex Mono** (둘 다 OFL이라 앱에 넣을 수 있음) |
| **색** | UI는 회색 단계만. 강조색 1개는 미정 (와이어프레임은 임시 파랑) |
| **아이콘** | 자체 제작 예정. 와이어프레임에는 회색 네모 자리만 |
| **친절함** | 도구에 이름을 항상 표시, 단축키는 도구 오른쪽 위 작은 글자로 |
| **예외** | 미리보기의 인스타 화면 재현 영역은 인스타 모양 그대로 (프로필 원, 둥근 배지) |

### 보면 볼수록 기능이 늘어나는 구조 (점진적 공개)

| 단계 | 보이는 것 |
|---|---|
| 1단계 · 늘 보임 | 이름 붙은 도구 바, 위치·크기, 글자, 채우기, 장 목록, 미리보기·내보내기 |
| 2단계 · 한 번 눌러서 | + 로 추가하는 배경 박스·테두리·효과, ▾ 펼치는 칸, 숨은 도구(작은 삼각형) |
| 3단계 · 익숙해지면 | 고급 설정(블렌드, 장평), 길게 누르기 메뉴, 단축키, 손가락 제스처 |

## 3. 흔해지지 않게 확인하는 방법

- **로고 가리기 테스트**: 앱 이름과 아이콘을 가려도 캐로킷 화면인지 알아볼 수 있나?
- **회색 점검**: 그냥 기본 회색(#F5F5F5 같은)을 쓰지 말고, 회색 단계도 직접 정한다 (살짝 따뜻하게 또는 차갑게)
- **간격 체계**: 여백과 크기를 정해진 단위(예: 4 또는 8의 배수)로만 쓴다
- **다크·라이트 둘 다**에서 같은 인상인지

## 4. 다음에 정할 것

| # | 정할 것 | 방법 |
|---|---|---|
| 1 | 키워드 3개 | 예: 정확한 / 조용한 / 든든한 |
| 2 | 시그니처 확정 | 위 후보 중 2~3개 |
| 3 | 강조색 | 후보 3~4개를 실제 에디터 화면에 넣어 비교 |
| 4 | UI 글꼴 | 시스템 글꼴(SF, Apple SD 산돌고딕 Neo) 또는 Pretendard. 숫자 글꼴 따로 |
| 5 | 핵심 화면 시안 | 에디터 화면 하나를 실제 아이패드 크기로 |
| 6 | 레퍼런스 | 미니멀하지만 아이덴티티 있는 툴과 제품 모으기 (무드보드) |
